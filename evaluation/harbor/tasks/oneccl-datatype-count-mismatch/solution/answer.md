The first defect is a violated collective contract, not worker affinity. For oneCCL allreduce, every rank in the communicator must enter the same sequence with a compatible operation, reduction, stream/dependency order, element `count`, and datatype. `count` is the number of elements of the declared datatype, not a byte length. BF16 storage described as float32 also makes the library compute the wrong extent and interpretation. Different extents across ranks can hang; a storage/datatype mismatch can overrun, truncate, or corrupt buffers. Affinity may change timing but cannot repair this contract.

Create one canonical flattened-gradient descriptor before submission: ordered tensor list, logical element count, padding policy, storage type, oneCCL datatype, reduction, communicator generation, and sequence ID. Broadcast or independently derive identical metadata and assert it on every rank. If padding is required, every rank must allocate and initialize the same padded element extent and pass that element count. The send and receive allocations must each hold `count * sizeof(dtype)` bytes (or the documented in-place form), with matching alignment and device/host placement. Map BF16 storage to the supported oneCCL BF16 datatype only after checking the installed oneCCL version and selected backend support; otherwise convert through an explicitly supported representation.

Retain the asynchronous event/request and wait, or provide a proven dependency chain, before unflattening, consuming the reduced gradients, reusing either buffer, or freeing temporary storage. Capture synchronous exceptions and completion status. Use per-rank asynchronous error/runtime evidence where the API and stream provide it.

Replace the current log with one rank-prefixed record immediately before submission and after completion. Record global/local rank, host and device, process ID, launcher, communicator identity/generation, collective sequence ID, operation and reduction, count in elements, datatype and `sizeof`/storage type, computed bytes, send/receive allocation bytes, in-place flag, tensor shapes/order/padding, buffer placement, stream, dependencies, oneCCL version/build, plugin/transport, workers, and affinity. A compact per-rank table or metadata hash should make the first divergent field obvious.

Reduce to two ranks, one communicator, one synchronous or explicitly waited allreduce, and a fixed small vector. For example, rank 0 supplies `[1, 2, 3, 4]` and rank 1 supplies `[10, 20, 30, 40]`; both must receive `[11, 22, 33, 44]` under sum. Run separate float32 and, only when supported, BF16 cases with stated tolerances. Compare every rank against a host reference, use guard regions or a memory checker to detect overwrite, and test one-element, odd, padded, and representative counts. Inject a metadata mismatch in a test that fails locally before entering the collective rather than hanging.

Only after all ranks complete and match the reference should performance work begin. Benchmark representative tensor sizes, rank counts, and topology with fixed plugin/transport and worker settings, warmup and repeated synchronized iterations. Report distribution and throughput. Tune affinity, workers, or transport one variable at a time; bound any claim to the tested collective contract, hardware, topology, and software versions.
